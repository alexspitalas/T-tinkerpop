=== Temporal Functionality Overview

==== 1. Multi-Interval Lifetime Management
Vertices, edges, and vertex properties support single and multi-interval validity timelines using half-open intervals `[start, end)`. Elements without explicit temporal properties are treated as static and alive forever (`Lifetime.UNBOUNDED`, `[-∞, +∞)`).

* **Steps**: `lifetime(start, end)`, `lifetime(start)`, `lifetimeProperty(key, val, start, end)`, `addInterval(start, end)`, `dropInterval(start, end [, DropMode])`, `getLifetime()`, `getStartTime()`, `getEndTime()`
* **Documentation**: xref:docs/src/reference/temporal-functionality.asciidoc#_lifetime_management[docs/src/reference/temporal-functionality.asciidoc — Lifetime Management]

[source,java]
----
// Set initial lifetime, split it with dropInterval(), and append a new active period with addInterval()
Vertex v = g.addV("contract").lifetime("2020-01-01", "2030-01-01").next();
g.V(v).dropInterval("2024-01-01", "2025-01-01").addInterval("2032-01-01", "2035-01-01").iterate();

// Assign a lifetime to a vertex property and retrieve the element's Lifetime object
g.V(v).lifetimeProperty("status", "active", "2020-01-01", "2024-01-01").iterate();
Lifetime lt = g.V(v).getLifetime().next();
----

==== 2. Temporal Views (`atTime` and `window`)
Filter elements alive at a snapshot instant or during a query window and automatically scope all subsequent graph navigation (`out()`, `in()`, `bothE()`, `has()`, `values()`, `properties()`) to that temporal context across both OLTP and OLAP (`g.withComputer()`).

* **Steps**: `atTime(instant)`, `window(start, end)`, `window(Lifetime)`
* **Documentation**: xref:docs/src/reference/temporal-functionality.asciidoc#_temporal_views[docs/src/reference/temporal-functionality.asciidoc — Temporal Views]

[source,java]
----
// Snapshot query at a single point in time
List<Vertex> activeAtInstant = g.V().atTime("2022-07-01T00:00:00Z").out("manages").toList();

// Windowed navigation (works in both OLTP and OLAP via TemporalGraphViewStrategy)
List<Vertex> activeInWindow = g.V().window("2022-01-01", "2023-01-01").out("manages").toList();
----

==== 3. Allen's Interval Algebra, `TemporalP`, & Ligozat's Generalized Interval Calculus
Provides all 13 of Allen's interval relations, `intersects`, gap-aware `disjoint`, convex lattice intervals (`TemporalP.between`), Vilain's point-interval relations, and Ligozat's $(p, q)$-relations (`TemporalP.generalized`) across single intervals, multi-interval lifetimes, and graph elements, with holistic (`ALL`, default) and existential (`ANY`) quantification.

* **Steps & Predicates**: `temporalBefore` (`temporalPrecedes`), `temporalAfter` (`temporalSucceeds`), `temporalMeets`, `temporalMetBy`, `temporalOverlaps`, `temporalOverlappedBy`, `temporalDuring`, `temporalContains`, `temporalStarts`, `temporalStartedBy`, `temporalFinishes`, `temporalFinishedBy`, `temporalEquals`, `temporalIntersects`, `temporalDisjoint`, and `TemporalP.*`
* **Documentation**: xref:docs/src/reference/temporal-functionality.asciidoc#_allens_interval_algebra_ligozats_generalized_interval_calculus[docs/src/reference/temporal-functionality.asciidoc — Allen's Interval Algebra & Ligozat's Generalized Interval Calculus]

[source,java]
----
// Direct traversal steps (supports .with(Temporal.ANY) or default Temporal.ALL)
g.V().hasLabel("Task").temporalDuring(projectVertex).toList();
g.V().hasLabel("Task").temporalBefore(projectVertex).with(Temporal.ANY).toList();

// Binary predicates in where() / has() / match() and convex lattice intervals
g.V().as("a").out("dependsOn").as("b").where("a", TemporalP.between(Temporal.precedes, Temporal.meets, "b")).toList();
----

==== 4. Temporal Path Filtering (`continuousPath`, `sequentialPath`, `pairwiseContinuousPath`)
Traverse multi-hop paths while enforcing time-respecting edge constraints (simultaneous intersection across the entire path, causal ordering with optional `[minDelay, maxDelay]`, or pairwise consecutive overlap with optional monotonicity).

* **Steps**: `continuousPath(labels...)`, `sequentialPath([minDelay, maxDelay,] labels...)`, `pairwiseContinuousPath([monotone,] labels...)`
* **Documentation**: xref:docs/src/reference/temporal-functionality.asciidoc#_temporal_paths[docs/src/reference/temporal-functionality.asciidoc — Temporal Paths]

[source,java]
----
// Continuous path (all edges in the path share a common overlapping time window)
g.V(startVertex).repeat(__.continuousPath("collaborates")).times(3).path().toList();

// Causal sequential path with bounded transition delay [minDelay, maxDelay] in ms
g.V(startVertex).repeat(__.sequentialPath(0L, 3600_000L, "processedBy")).until(__.has("status", "done")).path().toList();
----

==== 5. Temporal Shortest Paths (`tbfs` for OLTP & `temporalShortestPath` for OLAP)
Compute optimal time-respecting paths for `EARLIEST_ARRIVAL`, `EARLIEST_DEPARTURE`, `LATEST_ARRIVAL`, and `LATEST_DEPARTURE` over multi-interval edges locally via `tbfs()` or distributed on `GraphComputer` via `temporalShortestPath()`.

* **Steps**: `tbfs(target, initialTime)`, `tbfs(initialTime, target, direction, labels...)`, `temporalShortestPath([target, initialTime])`
* **Documentation**: xref:docs/src/reference/the-traversal.asciidoc#tbfs-step[docs/src/reference/the-traversal.asciidoc — TBFS Step] and xref:docs/src/reference/the-traversal.asciidoc#temporalshortestpath-step[docs/src/reference/the-traversal.asciidoc — TemporalShortestPath Step]

[source,java]
----
// OLTP Temporal BFS
Map<Vertex, Long> arrivals = g.V(sourceVertex).tbfs(TemporalPathTarget.EARLIEST_ARRIVAL, 1000L).next();

// OLAP Distributed Temporal Shortest Path on GraphComputer
List<Path> paths = g.withComputer().V(sourceVertex)
    .temporalShortestPath(TemporalPathTarget.EARLIEST_ARRIVAL, 1000L)
    .with(TemporalShortestPathVertexProgram.TARGET_VERTEX_FILTER, __.has("name", "target"))
    .toList();
----

==== 6. Temporal PageRank (`temporalPageRank`)
Rank vertices over a chronological stream of multi-interval edges where walk mass propagates forward in time as edges occur.

* **Step**: `temporalPageRank()` configured via `.with(TemporalPageRank.alpha, ...)`, `.with(TemporalPageRank.beta, ...)`, `.with(TemporalPageRank.propertyName, ...)`, `.with(TemporalPageRank.normalize, ...)`
* **Documentation**: xref:docs/src/reference/temporal-functionality.asciidoc#_temporal_pagerank[docs/src/reference/temporal-functionality.asciidoc — Temporal PageRank]

[source,java]
----
List<Vertex> ranked = g.V().hasLabel("person")
    .temporalPageRank()
    .with(TemporalPageRank.propertyName, "temporalRank")
    .with(TemporalPageRank.alpha, 0.85d)
    .with(TemporalPageRank.beta, 0.5d)
    .toList();
----

==== 7. Temporal Indexing & Optimization Strategies
TinkerGraph provides `TemporalTinkerIndex` backed by an augmented AVL `IntervalTree` for $O(\log N + K)$ interval lookups, alongside automatic traversal optimization strategies (`TemporalGraphStepStrategy`, `TemporalIndexOptimizationStrategy`, `TemporalGraphViewStrategy`).

* **Usage**: `graph.createIndex("temporalIntervals", Vertex.class)` / `graph.createIndex("temporalIntervals", Edge.class)`
* **Documentation**: xref:docs/src/reference/implementations-tinkergraph.asciidoc#temporal-tinkerindex[docs/src/reference/implementations-tinkergraph.asciidoc — Temporal Indexing and In-Memory Caching] and xref:docs/src/reference/temporal-functionality.asciidoc#_implementation_notes[docs/src/reference/temporal-functionality.asciidoc — Implementation Notes]

[source,java]
----
// Create a temporal index on vertices or edges; Allen steps and TemporalP predicates automatically use it
graph.createIndex("temporalIntervals", Vertex.class);
List<Vertex> matches = g.V().temporalIntersects(Lifetime.from("2023-01-01", "2023-06-01")).toList();
----

=== Building and Testing

TinkerPop uses link:https://maven.apache.org/[Maven] and requires `Java 11` for proper building and proper operations. To build, execute unit tests and package Gremlin Console/Server run:

[source,bash]
mvn clean install

Please see the xref:docs/src/dev/developer/development-environment.asciidoc#building-on-windows[Building on Windows] section for Windows specific build instructions.

The zip distributions can be found in the following directories:

. `gremlin-server/target`
. `gremlin-console/target`

Please see the link:https://tinkerpop.apache.org/docs/current/dev/developer/#_contributing[CONTRIBUTING.asciidoc] file for more detailed information and options for building, test running and developing TinkerPop.

=== Get Started

Download link:https://tinkerpop.apache.org/download.html[Gremlin Console] (compatible with Java 8/11) and unzip to a directory, then:

[source,bash]
----
$ bin/gremlin.sh

         \,,,/
         (o o)
-----oOOo-(3)-oOOo-----
plugin activated: tinkerpop.server
plugin activated: tinkerpop.utilities
plugin activated: tinkerpop.tinkergraph
gremlin> graph = TinkerFactory.createModern()
==>tinkergraph[vertices:6 edges:6]
gremlin> g = traversal().withEmbedded(graph)
==>graphtraversalsource[tinkergraph[vertices:6 edges:6], standard]
gremlin> g.V().has('name','vadas').valueMap()
==>[name:[vadas], age:[27]]
----

== Temporal Engine TODOs

* **Distributed Temporal PageRank (OLAP):** The current `TemporalPageRankStep` implements the Rozenshtein-Gionis algorithm for in-memory (OLTP) execution via chronological edge-streaming. A future enhancement should introduce `TemporalPageRankVertexProgram` to support this logic in distributed `GraphComputer` environments. This will require passing `(mass, timestamp)` pairs during BSP message passing to properly simulate chronological mass propagation across the cluster.
